# 项目定位：与「客户端型 / 授权型」工具的差别

> 查证日期：2026-09-23。本页只记录**公开仓库里可核实的事实**，不对任何第三方产品做评价。
> 目的：让维护者与使用者都清楚「为什么本项目走另一条路」，以及我们**刻意不做**什么。

## 一句话

不接管账号、不做检测规避；只在你自己的浏览器里，按人手该有的节奏，替你干重复劳动。

## 两个优势不在同一根轴上

- 它规避的是**指纹与自动化痕迹**（`navigator.webdriver`、CDP 特征、UA）—— 需要装 stealth 这件事本身就说明默认状态是被识别的；
- 本项目规避的是**行为幅度**（间隔、每日上限、只读为主、写操作必须手动点）；
- 风控判定通常是两者的**乘积**，而行为幅度往往权重更高。所以本项目的「反检测」不在插件里，而在硬编码的节奏里 —— 是设计出来的，不是运气。

## 我们的定位

1. **装完即用**：一个扩展 + 7 个小脚本，每份 1000~3000 行，全部可读；
2. **Cookie 不出浏览器**：没有服务器，不接收、不存储任何人的登录凭据，不代跑；
3. **默认克制**：会写账号的投递脚本（不公开分发）必须手动启动，默认每岗 10 秒、每日 50 个，撞限额即熔断；
4. **不假装是人**：不做指纹伪装、不做验证码绕过，把节奏放在人手该有的尺度上。

## 红线：明确不做的事

- 不做 `navigator.webdriver` / 指纹 / UA 伪装；
- 不做验证码绕过、代理池、多账号；
- 不做服务端代跑，不接收他人 Cookie；
- 不做自动翻页 / 全站抓取；
- 不接受「把投递速度调更快」类需求。

三条**实际**理由（不是道德说教）：

1. 定位一旦从「求职辅助」变成「绕过平台安全机制」，被投诉 / 下架的风险显著上升；
2. 对使用者账号而言，伪装的收益是「晚点被发现」，代价是「被发现时按规避处理」，净收益可能为负；
3. 这类代码一旦进入仓库历史，就永久绑定在项目上，无法回收。

## 我们做的「行为侧降特征」

| 措施 | 现状 | 落在哪 |
| --- | --- | --- |
| 间隔 + 每日上限 | 投递每岗 10 秒 / 每日 50（可调）；聊天 AI 判定每日 30；会话处置每日 30 | `boss-deliver` 的 `DEFAULTS`、`boss-chat` 的 `ai.maxPerDay`、`boss-insight` 的 `actPrecheck` |
| 只在可见标签页工作 | 5 个脚本都用 `document.visibilityState` 判断 | chat / filter / insight / tag / watcher |
| 多标签页不叠加额度 | 投递决策前先读盘合并（v1.4.8） | `boss-deliver` 的 `syncSet()` |
| 失败即停 / 熔断 / 冷却 | 额度风控→熔断；限流→冷却 15 分钟；对方侧→本条失败（三分类） | `boss-deliver` |
| 补详情限速 | 1.2~2.5 秒/条、每日 40；一致性体检单次 40、连败 3 次停 + 冷却 5 分钟 | `boss-filter`、`boss-consist` |
| 只被动读页面自己发的请求 | 不额外发请求，靠页面世界钩子回传 | `boss-chat`、`boss-watcher` |
| 写操作人工触发 + 二次确认 | 打招呼 / 拉黑 / 删除记录 | `boss-deliver`、`boss-insight` |
