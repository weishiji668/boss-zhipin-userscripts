# 从旧版本迁移

这份文档只解决一件事：**别让新旧两份脚本同时跑**。

## 为什么会同时跑两份

篡改猴是按 `@name` + `@namespace` 两个字段来认脚本的：

- 如果你从**同一个仓库**的同一个脚本升级，`@name`/`@namespace` 没变 → 是「更新」，不会重复。
- 如果你从**另一个来源**装过同名脚本（例如我早期本地开发时的版本，或另一个仓库的 fork），而 `@namespace` 不同 →
  篡改猴会当成**两个不同的脚本**，两份都注入、都运行。

症状很好认：**页面上出现两个一模一样的悬浮球**（今天就有用户踩到：两个 🩺 体检球）。
危害不只是难看 —— 两份会同时写同一批本机键，互相覆盖，你会看到面板数字来回跳。

## 迁移前：先备份能备份的

关键点：**本机数据分两处，换 `@namespace` 只会影响其中一处。**

| 数据 | 存在哪 | 换 namespace 后会怎样 | 怎么保住 |
| --- | --- | --- | --- |
| `filter` 规则、右键隐藏名单、公司/地点黑名单 | localStorage | **不受影响**（localStorage 只看域名） | 面板里本就有「导出规则」 |
| `tag` 规则与命中记录 | localStorage | 不受影响 | 面板「导出」 |
| `consist` 规则与处置清单 | localStorage | 不受影响 | — |
| `watcher` 监控清单 / 变更日志 / 设置 | 油猴存储 | **会读不到**（油猴存储按脚本隔离） | 面板「导出」→ JSON，装好新版后「导入」 |
| `chat` 会话归档 / 设置 | 油猴存储 | **会读不到** | 面板导出（复盘 CSV / 消息 CSV / JSONL） |

| `insight` 设置 / 处置流水 | 油猴存储 | **会读不到** | 面板导出；设置项需手动重设 |

## 迁移步骤

1. **备份**：把 `watcher` 的清单、`chat` 的会话数据导出一份，放到桌面。
2. **删旧**：打开篡改猴面板 → 已安装脚本列表 → 找到旧的那条（可以点开看 `@namespace` 与版本号）→ 删除。
   如果列表里出现两行**完全同名**的脚本（例如两行「聊天助手」），那就是重复安装，删掉版本低的那条。
3. **装新**：按 [install.md](install.md) 里的链接装当前版本。
4. **回填**：`watcher` 用「导入」把 JSON 放回去；`chat` 的导出是给人看的报表，主要用于对账，不自动回填。
5. **核对**：面板右下角版本号应等于仓库里的版本；页面上只应有一个悬浮球。

## 想回滚

最省事的做法：在篡改猴里找到该脚本 →「历史版本 / 以前的版本」→ 恢复到之前那版（篡改猴默认会保留最近若干版本）。
回滚后同样要 `Ctrl+Shift+R`。

## 给维护者

如果你打算改变 `@namespace`（例如从 `local.boss-*` 换成 `github.com/<user>/<repo>`），请：

1. 在 README 顶部加醒目的「升级必读：先删旧脚本」，并保留至少一个大版本周期。
2. 用 `npm run meta:set -- --namespace <新命名空间>` 统一改，别手改 7 个文件。
3. 发版说明里写清「换了 namespace，请先删旧脚本再装新版」，否则一定会有用户踩到重复安装。
