# 风险与安全边界

## 三类风险，先认清

| 风险 | 说明 |
| --- | --- |
| 账号风险 | 自动化行为可能触发风控：降权、限制沟通、封号。这是最大的风险，也是唯一无法靠代码完全消除的。 |
| 不可逆操作 | `boss-insight` 的拉黑 / 删除聊天记录无法撤销。 |
| 数据风险 | 导出文件里有 HR 姓名、联系方式、你的投递记录；本机键里也存着会话镜像。别把它们发到公开地方。 |

## 只有一个脚本会改你账号里的东西

| 脚本 | 动作 | 接口 | 护栏 |
| --- | --- | --- | --- |
| `boss-insight` | 标不感兴趣 / 拉黑 / 删除会话 | `zprelation` 系列 | 只在你点击时执行；二次确认；同一会话 10 秒冷却；每日上限 30；缺 `securityId` 或 `bst` 时直接拒绝，而不是硬发 |

## 其余脚本什么时候发请求

| 脚本 | 什么时候发 | 发什么 |
| --- | --- | --- |
| `boss-filter` | 只有你点「补取详情」 | 拉 `/job_detail/<id>.html` 读正文（有并发与频率限制，失败会冷却） |
| `boss-tag` | 从不 | 纯 DOM 判断 |
| `boss-watcher` | 你点「收录」时 | 1 次站内搜索 + 1 次详情；另有可选的定时只读检查（默认关） |
| `boss-chat` | 你点「一键收录」或开启 AI 判定时 | 读会话列表接口 / 调你自己配置的 AI 接口 |
| `boss-consist` | 你点「标记」/「隐藏」且需要补正文时 | 批量拉详情页：单次上限 40、连续失败 3 次即停并冷却 5 分钟 |

## 关于「一键投递」（不在本仓库）

第 7 个脚本 `boss-deliver` 是唯一会写账号的脚本，**不在本仓库分发**。它的限额语义（供已经拿到它的人参考）：`120 位` 先自动确认再继续；`150 位` / 验证码 → **当日熔断**；`操作过于频繁` → 只**冷却 15 分钟**；对方侧问题（职位已招满等）→ 只算这一条失败。自设上限默认 50 / 天。

> 自设上限（默认 50 / 天）是留了余量的保守值。平台侧真实上限约 120–150 / 天，但**别去顶它**：
> 额度顶满、节奏恒定不变，是最容易被风控盯上的形态。

## 关于浏览器调试端口

作者实测（未做独立复现）：站点页面会探测本机的常见调试端口。因此：

- **不要**在日常 / 求职账号上开着远程调试端口浏览招聘站点；
- 需要抓包调试时，用**独立的浏览器 profile + 一次性账号**；
- `tools/debug-browser.cjs` 这类脚本只用于本地 mock 页面，别拿去连真实站点。

## 隐私边界

- 数据只存本机；项目没有服务端，也不会把数据发给作者。
- 唯一的对外请求是：站点自身的接口（你浏览 / 点击触发），以及你**自己配置**的 AI 接口（可选功能）。
- 仓库里没有内置任何 API Key。CI 每次都会跑 `tools/scan-private.cjs`，拦截「本机路径 / 抓包文件 / 站方源码 / 疑似真实 key」。

## 把风险压到最低的做法

- 用**求职专用账号**，不要在办公设备 / 办公网络上跑。
- 投递量压在自设上限内；宁可分几天，也别一天顶满。
- 让 `boss-filter` 先把不想要的挡掉 —— 投递只作用于「过滤后可见」的岗位，这是最有效的省额度方式。
- 拉黑 / 删除前先看 `boss-insight` 给出的命中词（面板会显示是哪句话、哪个词命中）。
- 定期导出备份，别把导出文件留在共享盘或聊天窗口里。
- 一旦发现验证码 / 滑块频繁出现，先停几天。

## 明确不做的事

- 不提供账号、代理、代运营服务；
- 不做自动翻页 / 批量抓取全站；
- 不做多账号、代理池、验证码绕过；
- 不接受「提高批量投递速度」类需求。
